A Chrome extension starter with sign-in and payments already working

ExtensionKit is a Manifest V3 project in React, TypeScript and Vite. Users can create an account, run into a paywall, pay with Stripe or Lemon Squeezy, and get Pro features unlocked. What's left for you is the feature you want to charge for.

It isn't out yet. People on the list get one email at launch and the early-bird price.

What's in the repository

It's a normal Vite project, not a framework. These are the files that matter:

src/
  background/    # service worker: Supabase session, plan checks, opens checkout
  popup/         # sign-up, sign-in, plan card
  content/       # in-page button and paywall, inside a Shadow DOM
    proAction.ts # your paid feature goes here
  shared/        # typed messages and storage, used by every context
  config.ts      # name, button label and paywall copy
supabase/
  migrations/    # profiles table, row-level security, sign-up trigger
  functions/     # Stripe and Lemon Squeezy webhooks, signatures checked
docs/            # payment setup, Chrome Web Store, privacy policy template
tests/           # Vitest: messages, checkout links, webhook logic

About 1,500 lines of TypeScript in total. npm run check runs the type checker, ESLint, Prettier and the tests. There's also a script that generates a key so your extension ID is the same on every machine, which the sign-up confirmation link depends on.

How someone becomes Pro

You don't need a server of your own. Supabase holds the users and runs the webhook.

  1. The user clicks Upgrade to Pro. The service worker opens your Stripe Payment Link or Lemon Squeezy checkout with their Supabase user id attached.
  2. They pay on the provider's page, which handles cards, tax and receipts.
  3. The provider calls a Supabase Edge Function. It verifies the signature and sets is_pro on that user's profile.
  4. The next time the extension asks, the user is Pro. Refunds and cancelled subscriptions set it back to free.

Choosing between Stripe and Lemon Squeezy is one variable in .env. Lemon Squeezy works in countries where Stripe doesn't.

Gating a feature

This is the click handler of the in-page button, trimmed a little. Messages are typed, so the compiler knows CHECK_PRO_STATUS returns a boolean.

src/content/FloatingButton.tsx

const isPro = await sendToBackground('CHECK_PRO_STATUS').catch(() => false)
if (!isPro) {
  setShowPaywall(true)
  return
}
await runProAction()  // src/content/proAction.ts
setToast(config.proActionSuccess)

What you get, and what you don't

Included

  • All of the source code
  • Email and password sign-up with confirmation
  • Paywall dialog and plan card
  • Stripe and Lemon Squeezy webhooks
  • Unit tests, ESLint and Prettier set up
  • Guides for payments and the Web Store

Not included yet

  • Firefox and Safari builds
  • Google or other OAuth sign-in
  • Per-seat or team billing
  • Usage limits
  • Translations

Why I made it

In a paid extension, the feature is usually the quick part. The slow part is keeping a login working across a popup, a service worker that Chrome keeps putting to sleep, and scripts that run inside other people's websites, and then knowing who has paid. I did that part once, carefully, so you can start from it.

Questions

Who is it for?
Developers who want to sell a Chrome extension, whether it's a side project, a small SaaS or client work, and would rather not spend weeks on login and billing.
Do I need Stripe?
No. You can use Lemon Squeezy instead, which also handles sales tax for you.
Do I need a backend?
Only a Supabase project. The free tier is enough to start, and the webhooks run there as Edge Functions.
Can I use it for more than one product?
Yes, including client projects. What you can't do is resell the starter itself.
When does it come out?
Soon. The waitlist hears first.
