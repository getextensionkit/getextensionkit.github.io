Payments

From Upgrade to Pro, without a server of your own

Supabase stores the users and runs the webhook. You don't deploy or maintain anything else.

  1. Step 1The user clicks Upgrade

    The extension opens your checkout page with the user's id attached.

  2. Step 2They pay

    Stripe or Lemon Squeezy takes the card, handles tax and sends the receipt.

  3. Step 3The webhook confirms it

    An Edge Function verifies the signature and sets is_pro on the user.

  4. Step 4Pro unlocks

    Pro features start working. Refunds and cancellations switch them off again.

Switching provider is one line in .env. Lemon Squeezy works where Stripe isn't available. 
VITE_PAYMENT_PROVIDER=lemonsqueezy

Security

A paywall you can't patch out

Anyone can edit an installed extension, so a paywall that's only an if in the extension can be removed. Here the paid feature runs on Supabase, which checks the user's plan on every call.

// Runs on the server, only for users with is_pro = true.
export function textStats(input: unknown) {
  const text = requireText(input)
  const words = text.match(/\S+/g)?.length ?? 0
  return {
    words,
    readingMinutes: Math.max(1, Math.round(words / 230)),
  }
}

// Register yours next to it.
export const PRO_ACTIONS = {
  'text-stats': textStats,
}
// Runs in the page. Input and result are typed end to end.
export async function runProAction() {
  const text = document.body.innerText.slice(0, MAX_TEXT)
  const stats = await callProAction('text-stats', { text })
  return `${stats.words} words · ${stats.readingMinutes} min read`
}
const isPro = await sendToBackground('CHECK_PRO_STATUS')
if (!isPro) {
  setShowPaywall(true)
  return
}

try {
  setToast(await runProAction())
} catch (err) {
  // The server has the final say.
  if (err.message === PRO_REQUIRED) setShowPaywall(true)
}

Why I made it

In a paid extension, the feature is usually the quick part. The slow part is keeping a login alive across a popup, a service worker that Chrome keeps putting to sleep and scripts running inside other people's websites, and then knowing who has paid. I built that part once, carefully, so you can start from it.

Questions

Who is it for?

Developers who want to sell a Chrome extension, whether it's a side project, a small SaaS or client work, and would rather not spend weeks on login and billing.

Do I need Stripe?

No. You can use Lemon Squeezy instead, which also handles sales tax and works in countries Stripe doesn't support.

Do I need a backend?

Only a Supabase project. The free tier is enough to start, and the webhooks and Pro features run there as Edge Functions.

Can users get Pro by editing the extension?

They can make the paywall disappear, but the paid feature itself runs on the server and checks their plan each time, so they get a 402 instead of the result.

Can I use it for more than one product?

Yes, including client projects. The one thing you can't do is resell the starter itself.

When does it launch?
